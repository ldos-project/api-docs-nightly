Boosting the owners of contended PI futexes, and the lockprio.decisions OQueue.

The PI futex code reports the waiters of a futex and its owner whenever either changes, with the futex’s bucket locked, so the records here always reflect the latest state of each futex. The owner’s scheduling policy is then recomputed from those records by a LockPrioPolicy and applied with the global lock held, so concurrent changes for one owner are applied in order.

The policy is chosen with the lockprio.policy kernel parameter: inherit (the default) boosts like Linux’s priority inheritance, and none disables boosting.

Limitations:

  • Boosts are not propagated along chains: if a boosted owner is itself waiting for another futex, that futex’s owner sees the boosted policy only at the next change to that futex.
  • Changing a boosted thread’s policy with sched_setscheduler replaces its own policy, which it keeps once unboosted, but sched_getscheduler reports the boosted policy meanwhile. Threads it clones meanwhile do start with its own policy, as on Linux.

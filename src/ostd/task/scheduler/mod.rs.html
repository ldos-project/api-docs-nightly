3//! Task scheduling.
4//!
5//! # Scheduler Injection
6//!
7//! The task scheduler of an OS is a complex beast,
8//! and the most suitable scheduling algorithm often depends on the target usage scenario.
9//! To avoid code bloat and offer flexibility,
10//! OSTD does not include a gigantic, one-size-fits-all task scheduler.
11//! Instead, it allows the client to implement a custom scheduler (in safe Rust, of course)
12//! and register it with OSTD.
13//! This feature is known as **scheduler injection**.
14//!
15//! The client kernel performs scheduler injection via the [`inject_scheduler`] API.
16//! This API should be called as early as possible during kernel initialization,
17//! before any [`Task`]-related APIs are used.
18//! This requirement is reasonable since `Task`s depend on the scheduler.
19//!
20//! # Scheduler Abstraction
21//!
22//! The `inject_scheduler` API accepts an object implementing the [`Scheduler`] trait,
23//! which abstracts over any SMP-aware task scheduler.
24//! Whenever an OSTD client spawns a new task (via [`crate::task::TaskOptions`])
25//! or wakes a sleeping task (e.g., via [`crate::sync::Waker`]),
26//! OSTD internally forwards the corresponding `Arc<Task>`
27//! to the scheduler by invoking the [`Scheduler::enqueue`] method.
28//! This allows the injected scheduler to manage all runnable tasks.
29//!
30//! Each enqueued task is dispatched to one of the per-CPU local runqueues,
31//! which manage all runnable tasks on a specific CPU.
32//! A local runqueue is abstracted by the [`LocalRunQueue`] trait.
33//! OSTD accesses the local runqueue of the current CPU
34//! via [`Scheduler::local_rq_with`] or [`Scheduler::mut_local_rq_with`],
35//! which return immutable and mutable references to `dyn LocalRunQueue`, respectively.
36//!
37//! The [`LocalRunQueue`] trait enables OSTD to inspect and manipulate local runqueues.
38//! For instance, OSTD invokes the [`LocalRunQueue::pick_next`] method
39//! to let the scheduler select the next task to run.
40//! OSTD then performs a context switch to that task,
41//! which becomes the _current_ running task, accessible via [`LocalRunQueue::current`].
42//! When the current task is about to sleep (e.g., via [`crate::sync::Waiter`]),
43//! OSTD removes it from the local runqueue using [`LocalRunQueue::dequeue_current`].
44//!
45//! The interfaces of `Scheduler` and `LocalRunQueue` are simple
46//! yet (perhaps surprisingly) powerful enough to support
47//! even complex and advanced task scheduler implementations.
48//! Scheduler implementations are free to employ any load-balancing strategy
49//! to dispatch enqueued tasks across local runqueues,
50//! and each local runqueue is free to choose any prioritization strategy
51//! for selecting the next task to run.
52//! Based on OSTD's scheduling abstractions,
53//! the Asterinas kernel has successfully supported multiple Linux scheduling classes,
54//! including both real-time and normal policies.
55//!
56//! # Safety Impact
57//!
58//! While OSTD delegates scheduling decisions to the injected task scheduler,
59//! it verifies these decisions to avoid undefined behavior.
60//! In particular, it enforces the following safety invariant:
61//!
62//! > A task must not be scheduled to run on more than one CPU at a time.
63//!
64//! Violating this invariant—e.g., running the same task on two CPUs concurrently—
65//! can have catastrophic consequences,
66//! as the task's stack and internal state may be corrupted by concurrent modifications.

87/// Initialize scheduler globals.
88///
89/// This should be called before the scheduler runs for the first time, but after the allocator is
90/// fully initialized.
91pub(crate) fn init() {
92    #[cfg(all(feature = "capture_scheduling", not(baseline_asterinas)))]
93    SCHEDULING_EVENT_PRODUCER.call_once(|| {
94        use crate::{
95            orpc::oqueue::{GenericOQueueRef, OQueue, OQueueBase, registry},
96            path,
97        };
98
99        // TODO(arthurp): This calls the OQueue constructor before the scheduler is running. This is
100        // probably safe, but we should have documentation on when and why this is allowed.
101        let path = path!(scheduler.events);
102        let oqueue = GenericOQueueRef::new(1024, path.clone());
103
104        // Export the queue so it appears under the OQueue filesystem (e.g. at
105        // `/oqueues/scheduler/events`). The observer is revocable, so a slow userspace reader is
106        // dropped rather than blocking the scheduler.
107        registry::register_with(&path, &oqueue.as_any_oqueue());
108
109        oqueue.attach_ref_producer().unwrap()
110    });
111}

128/// Injects a custom implementation of task scheduler into OSTD.
129///
130/// This function can only be called once and must be called
131/// during the initialization phase of kernel,
132/// before any [`Task`]-related APIs are invoked.
133///
134/// # Panics
135///
136/// This function panics if a scheduler has already been injected,
137/// either explicitly via a previous call to this function
138/// or implicitly via the lazy default FIFO scheduler.
139pub fn inject_scheduler(scheduler: &'static dyn Scheduler<Task>) {
140    let mut is_new = false;
141    SCHEDULER.call_once(|| {
142        is_new = true;
143        scheduler
144    });
145    assert!(is_new, "a scheduler has already been initialized");
146}

148/// Enables preemptive scheduling on the current CPU.
149///
150/// After calling this function on a CPU,
151/// a task that is executing in the user mode may get preempted
152/// if another runnable task on the same CPU is deemed more urgent by the scheduler.
153///
154/// OSTD achieves task preemption by registering a per-CPU timer callback
155/// to invoke the scheduler periodically.
156/// Thus, this function should be called _once_ on every CPU
157/// by an OSTD-based kernel during its initialization phase,
158/// after it has injected its scheduler via [`inject_scheduler`].
159pub fn enable_preemption_on_cpu() {
160    timer::register_callback_on_cpu(|| {
161        scheduler_singleton().mut_local_rq_with(&mut |local_rq| {
162            let should_pick_next = local_rq.update_current(UpdateFlags::Tick);
163            if should_pick_next {
164                cpu_local::set_need_preempt();
165            }
166        })
167    });
168}

196/// Returns the global scheduler.
197///
198/// If a scheduler has already been injected (e.g., by a custom scheduler),
199/// it is returned directly. Otherwise, a default FIFO scheduler
200/// is lazily initialized and used.
201///
202/// Initialization is atomic: [`Once::call_once`] guarantees that even if
203/// multiple CPUs call this concurrently, only one will execute the

206    *SCHEDULER.call_once(|| fifo_scheduler::new_instance())

209/// A SMP-aware task scheduler.
210pub trait Scheduler<T = Task>: Sync + Send {
211    /// Enqueues a runnable task.
212    ///
213    /// The scheduler implementer can perform load-balancing or some time accounting work here.
214    ///
215    /// The newly-enqueued task may have a higher priority than the currently running one on a CPU
216    /// and thus should preempt the latter.
217    /// In this case, this method returns the ID of that CPU.
218    fn enqueue(&self, runnable: Arc<T>, flags: EnqueueFlags) -> Option<CpuId>;
219
220    /// Gets an immutable access to the local runqueue of the current CPU.
221    fn local_rq_with(&self, f: &mut dyn FnMut(&dyn LocalRunQueue<T>));
222
223    /// Gets a mutable access to the local runqueue of the current CPU.
224    fn mut_local_rq_with(&self, f: &mut dyn FnMut(&mut dyn LocalRunQueue<T>));
225
226    /// Return the amount of time spent in idle
227    fn idle_time(&self) -> Duration;
228}

230/// A per-CPU, local runqueue.
231///
232/// This abstraction allows OSTD to inspect and manipulate local runqueues.
233///
234/// Conceptually, a local runqueue maintains:
235/// 1. A priority queue of runnable tasks.
236///    The definition of "priority" is left to the concrete implementation.
237/// 2. The current running task.
238///
239/// # Interactions with OSTD
240///
241/// ## Overview
242///
243/// It is crucial for implementers of `LocalRunQueue`
244/// to understand how OSTD interacts with local runqueues.
245///
246/// A local runqueue is consulted by OSTD in response to one of four scheduling events:
247/// - **Yielding**, triggered by [`Task::yield_now`], where the current task voluntarily gives up CPU time.
248/// - **Sleeping**, triggered by [`crate::sync::Waiter::wait`]
249///   or any synchronization primitive built upon it (e.g., [`crate::sync::WaitQueue`], [`crate::sync::Mutex`]),
250///   which blocks the current task until a wake-up event occurs.
251/// - **Ticking**, triggered periodically by the system timer
252///   (see [`crate::timer::TIMER_FREQ`]),
253///   which provides an opportunity to do time accounting and consider preemption.
254/// - **Exiting**, triggered when the execution logic of a task has come to an end,
255///   which informs the scheduler that the task is exiting and will never be enqueued again.
256///
257/// The general workflow for OSTD to handle a scheduling event is as follows:
258/// 1. Acquire exclusive access to the local runqueue using [`Scheduler::mut_local_rq_with`].
259/// 2. Call [`LocalRunQueue::update_current`] to update the current task's state,
260///    returning a boolean value that indicates
261///    whether the current task should and can be replaced with another runnable task.
262/// 3. If the task is about to sleep or exit, call [`LocalRunQueue::dequeue_current`]
263///    to remove it from the runqueue.
264/// 4. If the return value of `update_current` in Step 2 is true,
265///    then select the next task to run with [`LocalRunQueue::pick_next`].
266///
267/// ## When to Pick the Next Task?
268///
269/// As shown above,
270/// OSTD guarantees that `pick_next` is only called
271/// when the current task should and can be replaced.
272/// This avoids unnecessary invocations and improves efficiency.
273///
274/// But under what conditions should the current task be replaced?
275/// Two criteria must be met:
276/// 1. There exists at least one other runnable task in the runqueue.
277/// 2. That task should preempt the current one, if present.
278///
279/// Some implications of these rules:
280/// - If the runqueue is empty, `update_current` must return `false`—there's nothing to run.
281/// - If the runqueue is non-empty but the current task is absent,
282///   `update_current` should return `true`—anything is better than nothing.
283/// - If the runqueue is non-empty and the flag is `UpdateFlags::WAIT`,
284///   `update_current` should also return `true`,
285///   because the current task is about to block.
286/// - In other cases, the return value depends on the scheduler's prioritization policy.
287///   For instance, a real-time task may only be preempted by a higher-priority task
288///   or if it explicitly yields.
289///   A normal task under Linux's CFS may be preempted by a task with smaller vruntime,
290///   but never by the idle task.
291///
292/// When OSTD is unsure about whether the current task should or can be replaced,
293/// it will invoke [`LocalRunQueue::try_pick_next`], the fallible version of `pick_next`.
294///
295/// ## Internal Working
296///
297/// To guide scheduler implementers,
298/// we provide a simplified view of how OSTD interacts with local runqueues _internally_
299/// in order to handle the four scheduling events.
300///
301/// ### Yielding
302///
303/// ```
304/// # use ostd::prelude::*;
305/// # use ostd::task::{*, scheduler::*};
306/// #
307/// # fn switch_to(next: Arc<Task>) {}
308/// #
309/// /// Yields the current task.
310/// fn yield(scheduler: &'static dyn Scheduler) {
311///     let next_task_opt: Option<Arc<Task>> = scheduler.mut_local_rq_with(|local_rq| {
312///         let should_pick_next = local_rq.update_current(UpdateFlags::Yield);
313///         should_pick_next.then(|| local_rq.pick_next().clone())
314///     });
315///     let Some(next_task) = next_task_opt {
316///         switch_to(next_task);
317///     }
318/// }
319/// ```
320///
321/// ### Sleeping
322///
323/// ```
324/// # use ostd::prelude::*;
325/// # use ostd::task::{*, scheduler::*};
326/// #
327/// # fn switch_to(next: Arc<Task>) {}
328/// #
329/// /// Puts the current task to sleep.
330/// ///
331/// /// The function takes a closure to check if the task is woken.
332/// /// This function is used internally to guard against race conditions,
333/// /// where the task is woken just before it goes to sleep.
334/// fn sleep<F: Fn() -> bool>(scheduler: &'static dyn Scheduler, is_woken: F) {
335///     let mut next_task_opt: Option<Arc<Task>> = None;
336///     let mut is_first_try = true;
337///     while scheduler.mut_local_rq_with(|local_rq| {
338///         if is_first_try {
339///             if is_woken() {
340///                 return false; // exit loop
341///             }
342///             is_first_try = false;
343///
344///             let should_pick_next = local_rq.update_current(UpdateFlags::Wait);
345///             let _current = local_rq.dequeue_current();
346///             if !should_pick_next {
347///                 return true; // continue loop
348///             }
349///             next_task_opt = Some(local_rq.pick_next().clone());
350///             false // exit loop
351///         } else {
352///             next_task_opt = local_rq.try_pick_next().cloned();
353///             next_task_opt.is_none()
354///         }
355///     }) {}
356///     let Some(next_task) = next_task_opt {
357///         switch_to(next_task);
358///     }
359/// }
360/// ```
361///
362/// ### Ticking
363///
364/// ```
365/// # use ostd::prelude::*;
366/// # use ostd::task::{*, scheduler::*};
367/// #
368/// # fn switch_to(next: Arc<Task>) {}
369/// # mod cpu_local {
370/// #     fn set_need_preempt();
371/// #     fn should_preempt() -> bool;
372/// # }
373/// #
374/// /// A callback to be invoked periodically by the timer interrupt.
375/// fn on_tick(scheduler: &'static dyn Scheduler) {
376///     scheduler.mut_local_rq_with(|local_rq| {
377///         let should_pick_next = local_rq.update_current(UpdateFlags::Tick);
378///         if should_pick_next {
379///             cpu_local::set_need_preempt();
380///         }
381///     });
382/// }
383///
384/// /// A preemption point, called at an earliest convenient timing
385/// /// when OSTD can safely preempt the current running task.
386/// fn might_preempt(scheduler: &'static dyn Scheduler) {
387///     if !cpu_local::should_preempt() {
388///         return;
389///     }
390///     let next_task_opt: Option<Arc<Task>> = scheduler
391///         .mut_local_rq_with(|local_rq| local_rq.try_pick_next().cloned())
392///     let Some(next_task) = next_task_opt {
393///         switch_to(next_task);
394///     }
395/// }
396/// ```
397///
398/// ### Exiting
399///
400/// ```
401/// # use ostd::prelude::*;
402/// # use ostd::task::{*, scheduler::*};
403/// #
404/// # fn switch_to(next: Arc<Task>) {}
405/// #
406/// /// Exits the current task.
407/// fn exit(scheduler: &'static dyn Scheduler) {
408///     let mut next_task_opt: Option<Arc<Task>> = None;
409///     let mut is_first_try = true;
410///     while scheduler.mut_local_rq_with(|local_rq| {
411///         if is_first_try {
412///             is_first_try = false;
413///             let should_pick_next = local_rq.update_current(UpdateFlags::Exit);
414///             let _current = local_rq.dequeue_current();
415///             if !should_pick_next {
416///                 return true; // continue loop
417///             }
418///             next_task_opt = Some(local_rq.pick_next().clone());
419///             false // exit loop
420///         } else {
421///             next_task_opt = local_rq.try_pick_next().cloned();
422///             next_task_opt.is_none()
423///         }
424///     }) {}
425///     let next_task = next_task_opt.unwrap();
426///     switch_to(next_task);
427/// }
428/// ```
429pub trait LocalRunQueue<T = Task> {
430    /// Gets the current runnable task.
431    fn current(&self) -> Option<&Arc<T>>;
432
433    /// Updates the current runnable task's scheduling statistics and
434    /// potentially its position in the runqueue.
435    ///
436    /// The return value of this method indicates whether an invocation of `pick_next` should be followed
437    /// to find another task to replace the current one.
438    #[must_use]
439    fn update_current(&mut self, flags: UpdateFlags) -> bool;
440
441    /// Picks the next runnable task.
442    ///
443    /// This method instructs the local runqueue to pick the next runnable task and replace the current one.
444    /// A reference to the new "current" task will be returned by this method.
445    /// If the "old" current task presents, then it is still runnable and thus remains in the runqueue.
446    ///
447    /// # Panics
448    ///
449    /// As explained in the type-level Rust doc,
450    /// this method will only be invoked by OSTD after a call to `update_current` returns true.
451    /// In case that this contract is broken by the caller,
452    /// the implementer is free to exhibit any undesirable or incorrect behaviors, include panicking.
453    fn pick_next(&mut self) -> &Arc<T> {
454        self.try_pick_next().unwrap()
455    }
456
457    /// Tries to pick the next runnable task.
458    ///
459    /// This method instructs the local runqueue to pick the next runnable task on a best-effort basis.
460    /// If such a task can be picked, then this task supersedes the current task and
461    /// the new the method returns a reference to the new "current" task.
462    /// If the "old" current task presents, then it is still runnable and thus remains in the runqueue.
463    fn try_pick_next(&mut self) -> Option<&Arc<T>>;
464
465    /// Removes the current runnable task from runqueue.
466    ///
467    /// This method returns the current runnable task.
468    /// If there is no current runnable task, this method returns `None`.
469    fn dequeue_current(&mut self) -> Option<Arc<T>>;
470}

472/// Possible triggers of an `enqueue` action.
473#[derive(Clone, Copy, PartialEq)]
474pub enum EnqueueFlags {
475    /// Spawn a new task.
476    Spawn,
477    /// Wake a sleeping task.
478    Wake,
479    /// Force a task to run next, effectively temporarily raising it's priority to the maximum
480    /// possible.
481    ForceSchedule,
482}

484/// Possible triggers of an `update_current` action.
485#[derive(Clone, Copy, PartialEq)]
486pub enum UpdateFlags {
487    /// Timer interrupt.
488    Tick,
489    /// Task waiting.
490    Wait,
491    /// Task yielding.
492    Yield,
493    /// Task exiting.
494    Exit,
495}

497/// Preempts the current task.
498#[track_caller]
499pub(crate) fn might_preempt() {
500    if !cpu_local::should_preempt() {
501        return;
502    }
503    reschedule(|local_rq| {
504        let next_task_opt = local_rq.try_pick_next();
505        if let Some(next_task) = next_task_opt {
506            ReschedAction::SwitchTo(next_task.clone())
507        } else {
508            ReschedAction::DoNothing
509        }
510    })
511}

513/// Blocks the current task unless `has_unparked()` returns `true`.
514///
515/// Note that this method may return due to spurious wake events. It's the caller's responsibility
516/// to detect them (if necessary).
517#[track_caller]
518pub(crate) fn park_current<F>(has_unparked: F)
519where
520    F: Fn() -> bool,
521{
522    let mut current = None;
523    let mut is_first_try = true;
524
525    reschedule(|local_rq: &mut dyn LocalRunQueue| {
526        let next_task_opt = if is_first_try {
527            if has_unparked() {
528                return ReschedAction::DoNothing;
529            }
530            is_first_try = false;
531
532            // Note the race conditions: the current task may be woken after the above `has_unparked`
533            // check, but before the below `dequeue_current` action, we need to make sure that the
534            // wakeup event isn't lost.
535            //
536            // Currently, for the FIFO and CFS scheduler, `Scheduler::enqueue` will try to lock `local_rq`
537            // when the above race condition occurs, so it will wait until we finish calling the
538            // `dequeue_current` method and nothing bad will happen. This may need to be revisited
539            // after more complex schedulers are introduced.
540
541            let should_pick_next = local_rq.update_current(UpdateFlags::Wait);
542            current = local_rq.dequeue_current();
543            should_pick_next.then(|| local_rq.pick_next())
544        } else {
545            local_rq.try_pick_next()
546        };
547
548        if let Some(next_task) = next_task_opt {
549            if Arc::ptr_eq(current.as_ref().unwrap(), next_task) {
550                // The current task has been woken and picked as the next runnable task.
551                return ReschedAction::DoNothing;
552            }
553            return ReschedAction::SwitchTo(next_task.clone());
554        }
555
556        ReschedAction::Retry
557    });
558}

560/// Unblocks a target task.
561pub(crate) fn unpark_target(runnable: Arc<Task>) {
562    // Refuse to schedule exited tasks.
563    if runnable.is_exited() {
564        return;
565    }
566
567    let preempt_cpu = scheduler_singleton().enqueue(runnable, EnqueueFlags::Wake);
568    if let Some(preempt_cpu_id) = preempt_cpu {
569        set_need_preempt(preempt_cpu_id);
570    }
571}
572
573/// Unblocks a target task and force it to run immediate, giving up the CPU to it if needed
574/// (similarly to yielding).
575pub(crate) fn switch_to_target(runnable: Arc<Task>) {
576    // Refuse to schedule exited tasks.
577    if runnable.is_exited() {
578        return;
579    }
580
581    let preempt_cpu = scheduler_singleton().enqueue(runnable, EnqueueFlags::ForceSchedule);
582    if let Some(preempt_cpu_id) = preempt_cpu {
583        set_need_preempt(preempt_cpu_id);
584        might_preempt();
585    }
586}

588/// Enqueues a newly built task.
589///
590/// Note that the new task is not guaranteed to run at once.
591#[track_caller]
592pub(super) fn run_new_task(runnable: Arc<Task>) {
593    let preempt_cpu = scheduler_singleton().enqueue(runnable, EnqueueFlags::Spawn);
594    if let Some(preempt_cpu_id) = preempt_cpu {
595        set_need_preempt(preempt_cpu_id);
596    }
597
598    // Only call might_preempt if there's an actual current task.
599    // During boot, there's no current task (we're in bootstrap context).
600    // If we preempt now, control transfers to the new task and boot never continues.
601    // TODO(yingqi): we might need a preempt guard here.
602    if processor::current_task().is_some() {
603        might_preempt();
604    }
605}

607/// Asks the CPU `cpu_id` to reschedule at its next preemption point.
608///
609/// A scheduler calls this when it changes a queued task's priority outside of
610/// [`Scheduler::enqueue`] so that the task now outranks the task running on that CPU.
611pub fn set_need_preempt(cpu_id: CpuId) {
612    let preempt_guard = disable_preempt();
613
614    if preempt_guard.current_cpu() == cpu_id {
615        cpu_local::set_need_preempt();
616    } else {
617        crate::smp::inter_processor_call(&CpuSet::from(cpu_id), || {
618            cpu_local::set_need_preempt();
619        });
620    }
621}

623/// Dequeues the current task from its runqueue.
624///
625/// This should only be called if the current is to exit.
626#[track_caller]
627pub(super) fn exit_current() -> ! {
628    if let Some(task) = Task::current() {
629        task.is_exited
630            .store(true, core::sync::atomic::Ordering::Release);
631    }
632
633    loop {
634        let mut is_first_try = true;
635
636        reschedule(|local_rq: &mut dyn LocalRunQueue| {
637            let next_task_opt = if is_first_try {
638                is_first_try = false;
639                let should_pick_next = local_rq.update_current(UpdateFlags::Exit);
640                let _current = local_rq.dequeue_current();
641                should_pick_next.then(|| local_rq.pick_next())
642            } else {
643                local_rq.try_pick_next()
644            };
645
646            if let Some(next_task) = next_task_opt {
647                ReschedAction::SwitchTo(next_task.clone())
648            } else {
649                ReschedAction::Retry
650            }
651        });
652
653        // The above reschedule should never return because the task exited. However, a buggy
654        // scheduler could return a task which already exited and cause it to run. To avoid this in
655        // all cases, the scheduler must perform some kind of synchronization between
656        // `update_current(Exit)` and `enqueue` on different LocalRunQueue implementation. Even
657        // without that, this is unreachable if task references do not outlive the task (which is
658        // the common case).
659        crate::warn!("Switched to already exited task.");
660    }
661}
662
663/// Yields execution.
664#[track_caller]
665pub(super) fn yield_now() {
666    reschedule(|local_rq| {
667        let should_pick_next = local_rq.update_current(UpdateFlags::Yield);
668        let next_task_opt = should_pick_next.then(|| local_rq.pick_next());
669        if let Some(next_task) = next_task_opt {
670            ReschedAction::SwitchTo(next_task.clone())
671        } else {
672            ReschedAction::DoNothing
673        }
674    })
675}

677/// Do rescheduling by acting on the scheduling decision (`ReschedAction`) made by a
678/// user-given closure.
679///
680/// The closure makes the scheduling decision by taking the local runqueue has its input.
681#[track_caller]
682fn reschedule<F>(mut f: F)
683where
684    F: FnMut(&mut dyn LocalRunQueue) -> ReschedAction,
685{
686    // Even if the decision below is `DoNothing`, we should clear this flag. Meanwhile, to avoid
687    // race conditions, we should do this before making the decision.
688    cpu_local::clear_need_preempt();
689
690    let next_task = loop {
691        let mut action = ReschedAction::DoNothing;
692        scheduler_singleton().mut_local_rq_with(&mut |rq| {
693            action = f(rq);
694        });
695
696        match action {
697            ReschedAction::DoNothing => {
698                return;
699            }
700            ReschedAction::Retry => {
701                continue;
702            }
703            ReschedAction::SwitchTo(next_task) => {
704                break next_task;
705            }
706        };
707    };
708
709    // This redefines `next_task` with the same value it started with, but moves the value out
710    // temporarily. This avoids an atomic incr and decr.
711    #[cfg(all(feature = "capture_scheduling", not(baseline_asterinas)))]
712    let next_task = {
713        let producer = get_scheduling_event_producer();
714        // Publish scheduling events best-effort: never block the scheduler on an observer. A full
715        // ring drops the event (and revokes a revocable observer), keeping the reschedule path
716        // fast and non-blocking.
717        if let Some(t) = Task::current() {
718            crate::ignore_err!(
719                producer
720                    .try_produce_ref(&SchedulingEvent {
721                        task: t.cloned(),
722                        kind: SchedulingEventKind::Deschedule,
723                    })
724                    .then_some(())
725                    .ok_or("scheduling event dropped: observer ring full"),
726                crate::log::Level::Notice
727            );
728        }
729
730        let scheduling_event = SchedulingEvent {
731            task: next_task,
732            kind: SchedulingEventKind::Schedule,
733        };
734        crate::ignore_err!(
735            producer
736                .try_produce_ref(&scheduling_event)
737                .then_some(())
738                .ok_or("scheduling event dropped: observer ring full"),
739            crate::log::Level::Notice
740        );
741        scheduling_event.task
742    };
743
744    // `switch_to_task` will spin if it finds that the next task is still running on some CPU core,
745    // which guarantees soundness regardless of the scheduler implementation.
746    //
747    // FIXME: The scheduler decision and context switching are not atomic, which can lead to some
748    // strange behavior even if the scheduler is implemented correctly. See "Problem 2" at
749    // <https://github.com/asterinas/asterinas/issues/1633> for details.
750    processor::switch_to_task(next_task);
751}
752
753/// Possible actions of a rescheduling.
754enum ReschedAction {
755    /// Keep running current task and do nothing.
756    DoNothing,
757    /// Loop until finding a task to swap out the current.
758    Retry,
759    /// Switch to target task.
760    SwitchTo(Arc<Task>),
761}

764pub fn idle_time() -> Duration {
765    SCHEDULER.get().unwrap().idle_time()
766}
